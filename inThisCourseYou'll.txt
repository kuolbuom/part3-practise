Let's understand the path itself:

- api — a common naming convention indicating that this endpoint belongs to the application's API.

Here's what happens when you send a GET request to http://localhost:3000/api/notes:
1. app.listen(3000) makes the application listen for incoming requests on port 3000.
2. app receives the request through the Express application.
3. get() checks whether the HTTP method is GET.
4. "/api/notes" identifies the path that must match.
5. The callback function runs Note.findAll() to retrieve all notes from the database.
6. res.json(notes) sends the notes back to the client as JSON.

1. Understand the actual problem
Look at this line:
SequelizeDatabaseError:
column "date" cannot be cast automatically to type timestamp with time zone


PostgreSQL is telling us:
- Your existing notes table has a column called date.
- Your Sequelize Note model now expects a different data type for that column.
- Sequelize is trying to change the existing column automatically.
- PostgreSQL cannot perform that conversion without an explicit instruction.
The SQL Sequelize is attempting to execute is:
ALTER TABLE "notes"
ALTER COLUMN "date"
TYPE TIMESTAMP WITH TIME ZONE;


2. Why is this happening?
Look at your error stack:
at async note.sync
at async syncModels (models/index.js:10:3)
at async start (index.js:22:3)


This tells us the problem happens during model synchronization, before your server finishes starting.

It is not caused by your login request.
3. Let's investigate before changing anything
Open your PostgreSQL terminal (psql) and execute this query:
SELECT
    column_name,
    data_type,
    is_nullable
FROM information_schema.columns
WHERE table_name = 'notes'

2. Modify your error handling middleware

const errorHandler = (error, req, res, next) => {

  if (

    error.name === "SequelizeUniqueConstraintError"

};


Why use error.errors.map()?

Sequelize can return multiple validation errors.
- error.errors contains the individual validation errors.
- .map() goes through each error.
- e.message extracts the message from each error.
This produces the array format required by the exercise.

For now, implement the token extractor:
const tokenExtractor = (request, response, next) => {
  const authorization = request.get("authorization");

  if (authorization && authorization.toLowerCase().startsWith("bearer ")) {
    request.token = authorization.substring(7);
  } else {
    request.token = null;
  }

  next();
};

module.exports = {
  tokenExtractor,
};


Understand what happens:

When a client sends a request, it includes an authorization header:
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

Your middleware:
1. Reads the authorization header.
2. Checks whether it starts with Bearer.
3. Extracts the token, removing Bearer .
4. Stores the token in request.token.
5. Calls next() to continue.
Notice that we haven't verified the token yet. We are only extracting it.
