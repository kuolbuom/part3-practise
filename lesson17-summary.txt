Good question! Testing does not automatically need its own port. Your normal application and testing application can use the same port, but they cannot listen on that port at the same time.

Let's understand the difference.
1. Port and database are two different things
Your application has two independent settings:
- Port: Where your application receives HTTP requests.
- Database: Where your application stores and retrieves data.
For example:
Normal application
Port 3000
defaultdb

http://localhost:3000

Testing application
Port 3001
test_db

http://localhost:3001

Here, we deliberately use different ports so both applications can run simultaneously.
2. Can they use the same port?
Yes!

For example:
Application	Port	Database
Normal	3000	defaultdb
Testing	3000	test_db

This works perfectly if you stop the normal application before starting the testing application.

But if you try to run both simultaneously on port 3000, you'll get a port conflict because only one server can listen on that port at a time.
3. What I recommend for your project
Keep this arrangement:
- Normal app: port 3000, database defaultdb.
- Testing app: port 3001, database test_db.
It makes it easier to distinguish them and reduces the risk of sending a testing request to your normal application.
