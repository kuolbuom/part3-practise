Almost right! Let's distinguish the two.

Your JSON response contains:
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VybmFtZSI6Im1hcnkyIiwiaWQiOjcsImlhdCI6MTc5MzE5MTIyMn0.NdAGB_8tg06DGX7oak7zhO_pDcTnFMzf9dYHBe6YciA",
  "username": "mary2",
  "name": "Mary Two"
}


1. Token: This is a JWT. It contains encoded information (the payload) and a digital signature.

2. Authorization header: This is how you send the token back to the server when making an authenticated request.

For example:
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJ1c2VybmFtZSI6Im1hcnkyIiwiaWQiOjcsImlhdCI6MTc5MzE5MTIyMn0.NdAGB_8tg06DGX7oak7zhO_pDcTnFMzf9dYHBe6YciA


3. Encoded information: Your JWT payload contains information such as:
{
  "username": "mary2",
  "id": 7,
  "iat": 1793191222
}


iat means the time the token was issued.
Remember the difference
- JWT = the token.
- Encoded = the representation of the payload inside the token.
- Authorization header = where you send the token in your HTTP request.
- Bearer = the authentication scheme.
Important: Your JWT is signed, not encrypted. Its payload can be decoded by anyone who has the token. Never put passwords or other secrets inside it.

Digital signature means: "A cryptographic mark created using a secret key to prove that data has not been changed and that it was signed by someone possessing the correct key."
Example in your JWT
Your JWT has three parts separated by dots (.):
header.payload.signature


For example:
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.
eyJ1c2VybmFtZSI6Im1hcnkyIiwiaWQiOjd9
.
NdAGB_8tg06DGX7oak7zhO_pDcTnFMzf9dYHBe6YciA


- Header: Describes the token algorithm.
- Payload: Carries information such as username and ID.
- Signature: Helps the server verify that the token has not been tampered with.
Simple example
Imagine the server signs this information:
{
  "username": "mary2",
  "id": 7
}


The server uses its secret key:
const token = jwt.sign(userForToken, SECRET)


When the client sends the token back, the server checks it:
jwt.verify(request.token, SECRET)


If someone changes the payload (for example, changes id: 7 to id: 1), the signature will no longer match, and verification fails.

Remember: A digital signature is like a security seal. It helps prove that the information has not been altered after signing.
