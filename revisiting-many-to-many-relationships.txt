Revisiting many-to-many relationships
Let's make another many-to-many relationship in the application. Each note is associated to the user who created it by a foreign key. It is now decided that the application also supports that the note can be associated with other users, and that a user can be associated with an arbitrary number of notes created by other users. The idea is that these notes are those that the user has marked for himself.

Let's make a join table user_notes for the situation. The migration, that is saved in file 20260211_04_add_user_notes.js is straightforward:

The file models/index.js, on the other hand, comes with a slight change to what we saw before:


const Note = require('./note')
const User = require('./user')

const UserNotes = require('./userNotes')

Note.belongsTo(User)
User.hasMany(Note)

User.belongsToMany(Note, { through: UserNotes, as: 'markedNotes' })

module.exports = {
  Note, User, Team, Membership, UserNotes
}
Once again, belongsToMany is used to link the user to the user's notes. The link is done via the join table that corresponds to the model UserNotes. However, this time we give an alias name for the attribute formed using the keyword as. The default name user.notes would overlap with its previous meaning, i.e., notes created by the user.

We extend the route for an individual user to return the user's teams, their own notes, and other notes marked by the user:


router.get('/:id', async (req, res) => {
  const user = await User.findByPk(req.params.id, {
    attributes: { exclude: [''] } ,
    include:[{
        model: Note,
        attributes: { exclude: ['userId'] }
      },
      {
        model: Note,
        as: 'markedNotes',
        attributes: { exclude: ['userId']},
        through: {
          attributes: []
        }
      },
      {
        model: Team,
        attributes: ['name', 'id'],
        through: {
          attributes: []
        }
      },
    ]
  })

  if (user) {
    res.json(user)
  } else {
    res.status(404).end()
  }
})
In the context of the include, we must now use the alias name markedNotes which we have just defined with the as attribute.

One important concept to understand:

You have two different relationships:
- notes.user_id connects a note directly to its owner.
- user_notes connects users and notes through a junction table.

Let's follow the execution logically:
Step 1: Start from user_notes
user_id	      note_id
3	            1
3	            2


Step 2: JOIN users
PostgreSQL matches user_notes.user_id with users.id.

Result: nyuel is user 3.

Step 3: JOIN notes

PostgreSQL matches user_notes.note_id with notes.id.

Result: It retrieves the two note contents.

How this relates to Sequelize
In Sequelize, you can represent this many-to-many relationship using:
User.belongsToMany(Note, { through: "UserNotes" });
Note.belongsToMany(User, { through: "UserNotes" });

Then retrieve a user's notes:
const user = await User.findByPk(3, {
  include: Note,
});

console.log(user.Notes);

The exact association property depends on your alias configuration.
