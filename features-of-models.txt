Features of models
There are some situations where, by default, we do not want to handle all the rows of a particular table. One such case could be that we don't normally want to display users that have been disabled in our application. In such a situation, we could define the default scope(opens in a new tab) for the model like this:


class User extends Model {}

User.init({
  // field definitions
}, {
  sequelize,
  underscored: true,
  timestamps: false,
  modelName: 'user',
  defaultScope: {
    where: {
      disabled: false
    }
  },
})

module.exports = User
Now the query caused by the function call User.findAll() has the following WHERE condition:


WHERE "user". "disabled" = false;
For models, it is possible to define other scopes as well:


User.init({
  // field definitions
}, {
  sequelize,
  underscored: true,
  timestamps: false,
  modelName: 'user',
  defaultScope: {
    where: {
      disabled: false
    }
  },
  scopes: {
    admin: {
      where: {
        admin: true
      }
    },
    disabled: {
      where: {
        disabled: true
      }
    },
    name(value) {
      return {
        where: {
          name: {
            [Op.iLike]: value
          }
        }
      }
    },
  }
})
Scopes are used as follows:


// all admins
const adminUsers = await User.scope('admin').findAll()

// all inactive users
const disabledUsers = await User.scope('disabled').findAll()

// users with the string jami in their name
const jamiUsers = await User.scope({ method: ['name', '%jami%'] }).findAll()
It is also possible to chain scopes:


// admins with the string jami in their name
const jamiUsers = await User.scope('admin', { method: ['name', '%jami%'] }).findAll()

3. Understand the SQL behind withNotes()
This is the most interesting part of the example.

The method uses three SQL concepts.

A. COUNT
sequelize.fn("COUNT", sequelize.col("notes.id"))


Counts how many notes belong to each user.

Conceptually:
COUNT(notes.id)


B. GROUP BY
group: ["user.id"]


Groups the notes according to their user.

For example:
User	Notes
Jami	5
Kuol	3
John	1

C. HAVING
having: sequelize.literal(`COUNT(notes.id) > ${limit}`)


Filters the groups after counting.

If you call:
User.withNotes(2);


The SQL condition is conceptually:
HAVING COUNT(notes.id) > 2;


The result contains Jami and Kuol, but not John.

One important safety improvement: the example uses sequelize.literal() with a template string. Avoid inserting untrusted request values directly into SQL literals. We can use parameterized expressions when implementing this in your application.

4. Where do these methods go?
Since your User model extends Sequelize's Model class, you define the methods inside that class.

For example, your models/user.js structure would look like this:
class User extends Model {
  // Instance method

    return (await this.getNotes()).length;
  }

  // Static method
  static async withNotes(limit) {
    // Database query goes here
  }
}

User.init(
  {
    // Your existing fields
  },
  {
    // Your existing Sequelize options
  },
);


Notice that both methods are inside the class, but outside User.init().
