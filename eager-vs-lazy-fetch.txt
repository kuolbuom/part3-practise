Eager vs lazy fetch
When we make queries using the include attribute:


User.findOne({
  include: {
    model: note
  }
})
This causes an eager fetch(opens in a new tab), i.e., all the rows of the tables attached to the user by the join query, in the example, the notes made by the user are fetched from the database at the same time. This is often what we want, but there are also situations where you want to do a lazy fetch, that is, search for user-related teams only if they are needed.

Let's now modify the route for an individual user so that it fetches the user's teams only if the query parameter teams is set in the request:


router.get('/:id', async (req, res) => {
  const user = await User.findByPk(req.params.id, {
    attributes: { exclude: [''] } ,
    include:[{
        model: Note,
        attributes: { exclude: ['userId'] }
      },
      {
        model: Note,
        as: 'markedNotes',
        attributes: { exclude: ['userId']},
        through: {
          attributes: []
        },
        include: {
          model: User,
          attributes: ['name']
        }
      },
    ]
  })

  if (!user) {
    return res.status(404).end()
  }

  let teams = undefined
  if (req.query.teams) {
    teams = await user.getTeams({
      attributes: ['name'],
      joinTableAttributes: []  
    })
  }
  res.json({ ...user.toJSON(), teams })
})
So now, the User.findByPk query does not retrieve teams, but they are retrieved if necessary by the user method getTeams, which is automatically generated by Sequelize for the model object. Similar get- and a few other useful methods are automatically generated(opens in a new tab) when defining associations for tables at the Sequelize level.

http://localhost:3001/api/users/3?teams=true

Notice that getTeams() is different from include.
- include retrieves associated records as part of the original findByPk query.
- user.getTeams() performs a separate association query when the condition is true.
